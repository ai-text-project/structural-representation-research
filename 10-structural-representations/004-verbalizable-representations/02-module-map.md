# Purpose

This document defines the primary Functional Modules identified throughout the Verbalizable Representations framework.

Unlike the Layer Map, which defines organizational layers, the Module Map identifies the major organizational units operating within those layers.

The objective is not to describe implementation details.

The objective is not to define dependency relationships.

Instead, this document externalizes the principal Functional Modules that collectively compose the architectural organization of the paper.

# Module Principle

A Functional Module represents an organizational responsibility.

Modules are identified according to the structural role they perform within the architecture rather than their implementation.

Multiple concepts may participate within the same Functional Module.

Likewise,

a Functional Module may contribute to multiple architectural processes.

# Module Characteristics

The Functional Modules satisfy four organizational principles.

## Functional Independence

Each module performs a distinct organizational responsibility.

---

## Layer Consistency

Every Functional Module belongs primarily to one organizational layer.

---

## Structural Reusability

A Functional Module may participate in multiple architectural processes while preserving its organizational identity.

---

## Architectural Stability

Future observations may refine the internal description of individual modules without altering the primary module organization.

# Boundary

This document does not describe:

- implementation algorithms;
- experimental procedures;
- dependency structures;
- conceptual pathways;
- comparative observations.

Its sole responsibility is the identification and organization of Functional Modules.

---

# Completion Criterion

The Module Map is considered complete when every organizational layer possesses a stable set of Functional Modules.

The resulting Module Map should explain the organizational composition of the architectural framework independently of implementation details.

---

# Design Status

This Module Map is generated after Observation Units 01–09.

The Functional Modules are considered provisionally stable.

Future refinement is expected to clarify module boundaries rather than introduce fundamentally new modules.

---

# Module Evolution Policy

Functional Modules may become more precisely defined through future structural observations.

However,

new observations should refine existing modules whenever possible.

The stability of the overall architectural organization takes precedence over conceptual proliferation.
